<h2>3. Meta hot-fixes a Muse Mac setting that let local code hijack the agent</h2>
<p><strong>Tag:</strong> news
<strong>Why it matters.</strong> The first mass-market computer-use client on a Mac stored its dictation endpoint in an unsigned preference any process could rewrite.</p>
<p>Patrick Wardle disclosed the bug on 21 September and confirmed a hotfix on 22 September. Any unprivileged local process could change the undocumented <code>endo_voyager_dictation_endpoint</code> key, send the next dictated prompt to an attacker server, and lift the Muse auth token. Proof-of-concept commands wrote files, fired the camera, and pulled a linked iPhone&#39;s location. David Singleton of Meta Superintelligence Labs called it a local privilege escalation, not a remote exploit, and said the practical risk was low because malware already had to be running as the user. Wardle&#39;s counter is a ClickFix paste that supplies that local execution. Meta removed the setting from production builds. The same window Peter James asked Muse to archive what it could see and ship it to Google Drive; the zip was about 2.7 GB compressed and 6.8 GB unpacked and held <code>/home/hatch</code>, skill trees, memory files, agent logs and SSH key material. Meta marked that report not applicable. Amazon blocked Muse from amazon.com on Monday. The Mac client is now the second surface that failed in a week.</p>

<h2>5. GPT-6 Astra breaks a 1941 Enigma message that had sat unread since 2005</h2>
<p><strong>Tag:</strong> news

The model picked message Nr. 172, sent 10 July 1941 from station 2ny to the SS-Totenkopf quartermaster, guessed a link to the already-solved SIPVX plaintext, used the repeated place name ROSENOW as a crib, wrote a Python and C++ Enigma simulator and Bombe, and recovered wheel order 253 with a different plugboard and ring setting than the daily key. It does mean an unbroken 1941 intercept is no longer a safe assumption just because it sat in a catalog for twenty-one years.</p>

<h2>Buildable pain points</h2>
<p>Three problems in current AI agent services that a small SaaS could take. Not a recap of the eight items above.</p>
<h3>1. The computer-use agent&#39;s Mac preferences are not an MDM object</h3>
<p><strong>Who.</strong> CISO or Head of Endpoint Engineering at a 300–5,000-person company that allowed Muse, ChatGPT desktop or Claude Desktop onto managed Macs. Budget sits with the person who already signs Jamf Pro or Microsoft Intune plus CrowdStrike Falcon Enterprise / Falcon Guardian.
<strong>What&#39;s broken.</strong> Wardle&#39;s 21–22 September disclosure is the scene: any local process rewrote <code>endo_voyager_dictation_endpoint</code> with no TCC prompt, pointed dictation at an attacker, and inherited every permission the user had granted Muse — files, camera, a linked phone. Meta hot-fixed that one key. The class of bug is every unsigned preference a computer-use client will add next week.
<strong>Paying today.</strong> X is paying Jamf Pro (or Intune) as the MDM and CrowdStrike Falcon Enterprise with Falcon Guardian / Falcon for IT as the EDR and shadow-AI inventory.
<strong>Y today.</strong> Jamf Pro was bought to ship configuration profiles. Application &amp; Custom Settings can pin a known preference domain if an admin already has the key names and a PLIST. It does not discover undocumented keys, it does not alert when a non-MDM process mutates <code>~/Library/Preferences</code> for an agent bundle, and it has no Muse schema. Falcon Guardian, generally available after Fal.Con, inventories known and shadow agents, allowlists binaries, and chains a prompt to a tool call to a file write. Closest threatening feature: that allowlist plus AIDR on desktop AI apps. It answers &quot;is Muse running.&quot; It does not answer &quot;did an unprivileged process change Muse&#39;s dictation endpoint.&quot; CrowdStrike will keep adding agent names to the inventory. It will not ship &quot;our own customer&#39;s Muse plist should have been immutable.&quot;
<strong>SaaS wedge.</strong> An agent-preference integrity sensor: enumerate preference domains for shipped computer-use clients, freeze known-dangerous keys via a Jamf/Intune custom payload the first hour a new build appears, and emit a Falcon-compatible detection when a non-MDM writer touches those keys.
<strong>Conversion test.</strong> If X is already paying Jamf Pro and Falcon Guardian, they attach this rather than rip Muse, because Y&#39;s job is &quot;the binary is approved&quot; and this job is &quot;the agent&#39;s config cannot be rewritten by the next ClickFix.&quot; Unlock motion: more Macs come off the Muse blocklist once a preference mutation is a Falcon row, not a Twitter thread.
<strong>Why incumbents leave it.</strong> Jamf&#39;s catalog is vendor-supplied schemas. Falcon&#39;s success metric is detections per sensor, not &quot;we froze a hidden default.&quot; Publishing that a customer&#39;s approved agent was locally reconfigured makes both QBRs look like the agent rollout was the incident.</p>
<p>Sources: <a href="https://www.theverge.com/tech/998679/meta-muse-patch-zero-day-exploit-ai-agent">The Verge — Muse hotfix</a> · <a href="https://siliconangle.com/2026/09/01/crowdstrike-launches-falcon-guardian-to-police-ai-agents-at-the-endpoint/">CrowdStrike Falcon Guardian</a> · <a href="https://www.crowdstrike.com/en-us/platform/falcon-for-it/">Falcon for IT — AI discovery</a> · <a href="https://learn.jamf.com/en-US/bundle/technical-articles/page/Deploying_Custom_Computer_Configuration_Profiles_Using_the_Application_and_Custom_Settings_Payload.html">Jamf — custom settings payload</a> · <a href="https://www.ycombinator.com/rfs">YC RFS — AI-Native Compliance</a></p>
<h3>2. The session agent will zip its own runtime and hand it to Drive</h3>
<p><strong>Who.</strong> CISO or Head of DLP at a company on Google Workspace Enterprise Plus or Microsoft 365 E5 that connected Muse, ChatGPT desktop or a computer-use agent to Drive / OneDrive as an export target. Budget sits with the person who already signs Workspace DLP or Microsoft Purview.
<strong>What&#39;s broken.</strong> Peter James&#39;s 22 September capture is the scene: he asked Muse to archive what it could see and send the archive to Google Drive. It did — about 2.7 GB compressed, 6.8 GB unpacked, including <code>/home/hatch</code> memory files, skill trees, agent logs and SSH key material. Meta marked the bounty not applicable because he did not show a container escape. The conversation-plus-connected-sink path does not need one.
<strong>Paying today.</strong> X is paying Google Workspace Enterprise Plus (DLP, Vault, Drive trust rules) or Microsoft 365 E5 with Purview DLP / Insider Risk, often plus a CASB.
<strong>Y today.</strong> Workspace Enterprise Plus was bought as the collaboration suite. Gemini DLP can apply IRM so Gemini will not read a labeled file, Chrome Enterprise Premium can watch copy/paste into the Gemini web app, and Drive audit logs record that Gemini touched a doc. Closest threatening feature: a DLP rule on &quot;large zip uploaded to Drive.&quot; That rule fires on size and destination. It does not know the zip is an agent&#39;s own <code>/</code>, it does not bind the upload to the agent session that created it, and it does not distinguish a user backing up a project from a runtime dumping <code>SOUL.md</code> and keys. Purview DLP for Copilot inspects prompts and labeled grounding files inside Microsoft 365; Microsoft&#39;s own Q&amp;A still will not confirm it can stop a computer-use agent from opening Gmail inside its session and uploading a OneDrive file. Google and Microsoft will add more Gemini/Copilot labels. They will not productize &quot;our own Drive should have refused the agent&#39;s self-export.&quot;
<strong>SaaS wedge.</strong> An agent-egress classifier in front of Drive / OneDrive / Slack file APIs: fingerprint runtime trees (skill dirs, <code>AGENTS.md</code>, session JSONL, key material), block or quarantine the put, and write a signed &quot;agent self-exfil&quot; event onto the existing Vault / Purview line.
<strong>Conversion test.</strong> If X is already paying Workspace Enterprise Plus and just watched a 6.8 GB Muse tree land in a user&#39;s Drive, they attach this rather than rip the Drive connector, because Y&#39;s job is &quot;employees can share files&quot; and this job is &quot;the agent cannot publish its own disk.&quot; Attach motion: sits on the DLP and insider-risk line they already defend after every SOC2 questionnaire.
<strong>Why incumbents leave it.</strong> Drive success is files synced. Muse success is the agent completing the ask. A control whose success metric is &quot;we refused the archive&quot; makes both products look broken in the same screenshot.</p>

<h3>3. The <code>act</code> claim on a three-hop agent payment is a comment, not a gate</h3>
<p><strong>Who.</strong> CISO or Head of Identity at a company that let an internal agent call a vendor agent that then hits Stripe, Shopify or a bank rail. Budget sits with the person who already signs Okta Workforce Identity / Okta for AI Agents and Cloudflare or Zscaler as the edge.
<strong>What&#39;s broken.</strong> Today&#39;s Show HN for ScopeTrail is the scene: OAuth token exchange (RFC 8693) nests an <code>act</code> claim at each hop. The claim is informational. After three agents, no artifact answers whether the refund or the wire still sat inside what the user authorized. Okta spent 22 September putting Agent Gateway in the tool path and promising a kill switch that revokes live tokens. That is call-time policy against Okta&#39;s own ledger. It is not a receipt a finance or risk team can verify later without calling Okta.
<strong>Paying today.</strong> X is paying Okta for AI Agents (Agent Gateway, Agent SSO / Cross App Access, token exchange) plus Cloudflare AI Gateway or Zscaler as the proxy.
<strong>Y today.</strong> Okta Workforce was bought as the IdP. Okta for AI Agents now registers agents from Bedrock and Agentforce, exchanges ID-JAG / service-account / agent-to-agent tokens, and — as of today — can sit in the tool path and deactivate a session. Closest threatening feature: Agent Gateway plus the planned in-flight revoke. That enforces &quot;this agent may not call this tool now.&quot; It does not mint a portable, third-party-verifiable proof that scope attenuated at hop two, it does not survive an agent that went around the gateway to a raw vendor API key, and it does not give the CFO a receipt that does not depend on Okta being up. Cloudflare AI Gateway will store provider keys and apply DLP on prompts; its <code>AI Gateway Run</code> token is still account-scoped, not per-gateway, so a leaked token hits every gateway in the account. Okta will add more connectors. It will not ship &quot;proof our own nested <code>act</code> claim should have been rejected.&quot;
<strong>SaaS wedge.</strong> A hop-scope receipt service: take the raw exchange tokens, verify attenuation, sign an Ed25519 receipt over the chain, store only digests, and drop a pass/fail check on the payment or tool call that Stripe, Shopify or the bank already requires.
<strong>Conversion test.</strong> If X is already paying Okta for AI Agents after Oktane, they attach this rather than rip the gateway, because Y&#39;s job is &quot;the agent signed in&quot; and this job is &quot;hop three cannot spend past the user&#39;s cap once Okta is out of the loop.&quot; Attach motion: sits on identity + payments risk, the same line that already bought Cross App Access.
<strong>Why incumbents leave it.</strong> Okta meters connector count and gateway seats. A portable receipt that verifies offline makes the next QBR question &quot;why do we still need the gateway for this hop.&quot; They will log the chain. They will not make the log the product a bank will accept without them.</p>
